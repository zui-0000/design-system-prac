# コンポーネントの置き方

記録日: 2026-10-18

`src/components/` の下を、どこでも使う部品（`ui/`）、機能ごとの部品（`features/`）、ページ（`pages/`）に分けた。部品とページでは、ファイルの名前の付け方が違う。Claude Code 向けには `.claude/rules/components.md` に同じ決まりを書いている。

## 構成

```
src/components/
├── ui/                  部品
│   └── Card/
│       ├── Card.tsx
│       ├── Card.module.css
│       └── Card.stories.tsx
├── features/            機能ごとの部品
│   └── Card/            機能（Card）
│       └── CardList/
│           ├── CardList.tsx
│           └── CardList.module.css
└── pages/               ページ
    └── Practice/
        ├── index.tsx    export function PracticePage()
        └── index.module.css
```

| 置き場所    | ファイル名                                  | 使われ方                                       |
| ----------- | ------------------------------------------- | ---------------------------------------------- |
| `ui/`       | 部品の名前（`Card.tsx`・`Card.module.css`） | ページやほかの部品から、何度も組み合わせて使う |
| `features/` | 部品の名前（`CardList.tsx`）                | その機能の中で使う                             |
| `pages/`    | `index.tsx`・`index.module.css`             | `src/routes/` から 1 回だけ使う。URL と 1 対 1 |

どちらも **1 つのフォルダに 1 つ**（部品なら 1 部品、ページなら 1 ページ）。TS で言えば package by feature で、関係するファイルが 1 か所にまとまり、消すときもフォルダごと消せる。

## `ui/` と `features/` の分け方

| 置き場所    | 置くもの                                                    | 例                      |
| ----------- | ----------------------------------------------------------- | ----------------------- |
| `ui/`       | どの機能でも使える、汎用の部品                              | Card、Button、Dialog    |
| `features/` | 特定の機能に結びついた部品。`features/<機能名>/` の下に置く | Card の一覧（CardList） |

CardList は、`children` を Grid で並べるだけなので、汎用の部品（`AutoGrid` など）にもできた。しかし「Card を一覧で見せる」ための部品として作ったので、汎用にはせず、Card という機能の部品として `features/Card/` に置いた。汎用にすると、名前から「何のための部品か」が分からなくなり、使われない設定も増えやすい。ほかの機能でも同じ並べ方が要るようになったら、そのときに `ui/` へ切り出す。

**依存の向きは `pages/` → `features/` → `ui/` の一方向。** `features/` は `ui/` を使ってよいが、`ui/` は `features/` を使わない。汎用の部品が特定の機能に依存すると、汎用でなくなるため。TS で言えば、共有ライブラリのパッケージがアプリのパッケージを import しないのと同じ。

**ストーリーを書くのは `ui/` だけ。** Storybook はデザインシステムの部品を一覧にして管理するために使っていて、機能ごとの部品はその対象ではない。`features/` の部品の見た目は、`/practice` などのページで確かめる。

`features/Card/` の「Card」は練習のための名前。実際のアプリなら、`features/Product/`（商品）や `features/Article/`（記事）のように、扱うデータの名前になる。

## 部品（`ui/`・`features/`）は名前付きのファイルにする

部品は、**パーツの組み合わせ**で作ることが多い。

```tsx
<Card>
  <CardHeader>
    <CardTitle>見出し</CardTitle>
  </CardHeader>
  <CardContent>本文</CardContent>
</Card>
```

パーツごとにファイルを分けると、1 つのフォルダに何枚も入る。

```
ui/Card/
├── Card.tsx
├── CardTitle.tsx
├── CardFooter.tsx
└── Card.module.css
```

本体だけを `index.tsx` にすると、どれが本体か名前から分からなくなる。名前をそろえておけば、ファイルの一覧がそのまま部品の設計図になる。全部が `index.tsx` だと、エディタのタブで見分けにくいという問題もある。

ストーリー（`Card.stories.tsx`）も同じフォルダに置き、部品を作ったら必ず書く。Storybook で一覧にするのがこのリポジトリの目的のため。

### パーツを 1 ファイルにまとめるか分けるか（未決定）

ライブラリによって書き方が違う。

| ライブラリ | パーツの書き方                                                             | ファイル                                         |
| ---------- | -------------------------------------------------------------------------- | ------------------------------------------------ |
| shadcn/ui  | `Card`・`CardHeader`・`CardTitle` などを別々の名前で export                | `components/ui/card.tsx` の 1 ファイルにまとめる |
| Base UI    | `Dialog.Root`・`Dialog.Trigger`・`Dialog.Popup` のように名前空間でまとめる | ライブラリ側にある。使う側はラップする           |

段階 3（Base UI + CSS Modules）で、パーツのある部品を作るときに決める。どちらにしても「`index.tsx` にしない、名前付きのまま」という決まりは変わらない。

## ページ（`pages/`）は `index.tsx` にする

ページは 1 枚で完結し、パーツに分けて外から組み合わせることがない。`Practice/index.tsx` で「Practice フォルダの中身がページ本体」と読めれば十分。

- フォルダ名はページの名前（PascalCase）。関数名は `PracticePage` のように `Page` を付ける
- import はフォルダまで書けば、中の `index.tsx` が読まれる（`"../components/pages/Practice"`）。npm のパッケージで、入口の `index.js` が読まれるのと同じ仕組み
- 経路の宣言はページに書かず、`src/routes/` に書く（[docs/07](07-ルーティング.md)）

## 依存の向きを検査する

依存の決まりは、ルールや docs に書くだけでは守られない（[docs/03](03-UX%20のルール.md) の「ルールは強制ではなく文脈」）。そこで [dependency-cruiser](https://github.com/sverweij/dependency-cruiser) で import を検査し、違反があればコミットを止める。

### 禁止している import

| ルール名                | 禁止する import                           | 理由                                                                                         |
| ----------------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------- |
| `ui-not-to-others`      | `ui/` → `features/`・`pages/`・`layouts/` | 汎用の部品が、特定の機能・ページ・枠に依存しないように                                       |
| `features-not-to-pages` | `features/` → `pages/`                    | 依存の向きを `pages/` → `features/` → `ui/` に保つ                                           |
| `no-cross-feature`      | `features/A/` → `features/B/`             | 機能どうしを絡ませない。共有したいものは `ui/` に出す                                        |
| `no-cross-page`         | `pages/A/` → `pages/B/`                   | ページどうしを絡ませない                                                                     |
| `no-circular`           | 循環参照（A → B → A）                     | 読み込みの順番によって、import した値が undefined になる（[docs/09](09-import%20のパス.md)） |

同じ機能・同じページの中の import は許している。正規表現でキャプチャした名前を、別の条件で `$1` として使える。

```jsonc
// .dependency-cruiser.jsonc
{
  "name": "no-cross-feature",
  "from": { "path": "^src/components/features/([^/]+)/" },
  "to": {
    "path": "^src/components/features/",
    "pathNot": "^src/components/features/$1/", // 同じ機能の中なら OK
  },
}
```

`import type` だけの import も検査される。TS で言えば、モノレポでパッケージどうしの依存を縛るのと同じことを、1 つのアプリの中のフォルダで行っている。

### 違反したときの文言は日本語にする

ルールの `comment` に、違反したときに表示する文言を書いている。出力の形式を `err-long` にすると、ルール名の下に `comment` が表示される（`package.json` の `lint:deps` で `--output-type err-long` を指定）。

```
  error no-cross-page: src/components/pages/Other/index.tsx → src/components/pages/Practice/index.tsx
    別のページを import しています。共有したい部品は ui/ か features/ に移してください（docs/06）

x 1 dependency violations (1 errors, 0 warnings). 21 modules, 26 dependencies cruised.
```

標準の形式（`err`）では、ルール名とファイルしか表示されない。最後の集計の行は英語のまま。

### いつ動くか

| 場面             | 動き                                                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 自分で実行する   | `vp run lint:deps`                                                                                                      |
| コミットするとき | `src/` の `.ts`・`.tsx` をステージしていれば、`vite.config.ts` の `staged` から自動で動く。違反があるとコミットが止まる |

`staged` では、コマンドを文字列ではなく関数で書いている。文字列だと、ステージしたファイルの名前が引数に付く（`depcruise src ... a.tsx b.tsx`）。依存の検査は `src/` 全体をたどる必要があるので、関数にして引数を付けずに実行している。

```ts
// vite.config.ts
staged: {
  "*": "vp check --fix",
  "src/**/*.{ts,tsx}": () => "vp run lint:deps",
},
```

### TypeScript 7 では swc で読む（つまずいたところ）

最初は標準の設定で動かしたところ、`no dependency violations found (0 modules, 0 dependencies cruised)` と出た。違反がないのではなく、**ファイルを 1 つも読めていなかった**。

```
‼ missing-typescript-transpiler: ... not a compatible TypeScript compiler (typescript: >=2.0.0 <7.0.0)
=> Support for typescript@>=7 will follow when its API is published and stable.
```

dependency-cruiser は、TS のファイルを読むのに `typescript` パッケージの JS の API を使う。TypeScript 7 は Go で書き直された版で、その API がまだない。しかも読めなくてもエラーにならず、「違反なし」で通ってしまう。

そこで、TS と JSX を読める [swc](https://swc.rs/)（Rust 製）で読むようにした。

```jsonc
// .dependency-cruiser.jsonc
"options": { "parser": "swc" }
```

- `@swc/core` を devDependencies に入れた。インストール時のスクリプトは pnpm に止められるので、esbuild と同じく `pnpm-workspace.yaml` の `allowBuilds` に `"@swc/core": false` と書いた。スクリプトを動かさなくても、問題なく動く
- swc で読めていても、上の `missing-typescript-transpiler` の警告は毎回出る。害はない
- 検査の結果に出る `modules` の数が 0 になっていたら、読めていない。設定を変えたときは、この数を確かめる
- dependency-cruiser が TypeScript 7 に対応したら、`parser` の指定と `@swc/core` を外せるか見直す

### 設定ファイルを `.jsonc` にした

コメントを書けるようにするため。dependency-cruiser は、`.js` などでない設定ファイルを JSON5 として読むので、コメントを書ける。

末尾のカンマも JSON5 なら読めるが、VS Code は JSONC の末尾のカンマに警告を出す。しかも Oxfmt は、標準の設定で末尾にカンマを付けて整形する。そこで `vite.config.ts` の `fmt.overrides` で、`.jsonc` だけ `trailingComma: "none"` にした。

```ts
// vite.config.ts
fmt: {
  overrides: [{ files: ["**/*.jsonc"], options: { trailingComma: "none" } }],
},
```

ただし、標準で探すファイル名（`.dependency-cruiser.js`・`.cjs`・`.mjs`・`.json` など）に `.jsonc` は入っていないので、`--config .dependency-cruiser.jsonc` で指定している（`package.json` の `lint:deps`）。
