# ルーティング

記録日: 2026-10-18

[TanStack Router](https://tanstack.com/router) のファイルベースルーティングを入れた。Claude Code 向けには `.claude/rules/routing.md` に同じ決まりを書いている。

## 入れたもの

| パッケージ                               | バージョン | 役割                                                             |
| ---------------------------------------- | ---------- | ---------------------------------------------------------------- |
| `@tanstack/react-router`                 | 1.170.44   | ルーター本体                                                     |
| `@tanstack/router-plugin`（dev）         | 1.168.46   | `src/routes/` から `src/routeTree.gen.ts` を作る Vite プラグイン |
| `@tanstack/react-router-devtools`（dev） | 1.167.2    | 画面の右下に出る開発用ツール。本番ビルドでは何も描かない         |

### 最新より 1 つ前にした理由

2026-10-17 の時点の最新は、本体 1.170.45・プラグイン 1.168.47 だった。どちらも前日の夜に公開されたばかりだった。

pnpm には、公開されて間もないバージョンを入れない仕組み（`minimumReleaseAge`）がある。乗っ取られたパッケージが、見つかる前に広まるのを防ぐため。最新を指定して `vp add` すると、pnpm が `pnpm-workspace.yaml` の `minimumReleaseAge` の例外（`minimumReleaseAgeExclude`）に、そのバージョンを書き足した。守りを外すことになるので取り消し、1 つ前のバージョンを入れた。

最新に上げるのは、数日たってから `vp update` で行う。

## 構成

```
src/
├── main.tsx            #root に App を描く
├── App.tsx             ルーターを作る。型の登録と devtools もここ
├── routeTree.gen.ts    自動生成。手で触らない
├── routes/             経路の宣言だけを置く
│   ├── __root.tsx      根。すべてのページの外側
│   ├── index.tsx       /（/practice へ転送する）
│   └── practice.tsx    /practice
└── components/pages/   画面の本体（docs/06）
```

**`routes/` には経路の宣言だけを書き、画面の中身は `components/pages/` に置く。** 経路の宣言と画面の中身を分けておくため。

```tsx
// src/routes/practice.tsx
import { createFileRoute } from "@tanstack/react-router";

import { PracticePage } from "../components/pages/Practice";

export const Route = createFileRoute("/practice")({
  component: PracticePage,
});
```

## ファイル名が URL になる

| ファイル              | URL              |
| --------------------- | ---------------- |
| `routes/index.tsx`    | `/`              |
| `routes/practice.tsx` | `/practice`      |
| `routes/user/$id.tsx` | `/user/123` など |

- `index.tsx` は、親の URL にちょうど一致したときのページ
- **経路でないファイルを `routes/` に置かない。** 置くと、プラグインが「Route を export していない」と警告する。どうしても置くなら、名前の先頭に `-` を付けると対象から外れる

## `/` は `/practice` へ転送する

`/` に来たら、`beforeLoad` で `redirect` を投げて `/practice` へ送る。`beforeLoad` は描画の前に走り、そこで投げると以降（`loader`・`component`）は動かない。だから `component` は書かない。

```tsx
// src/routes/index.tsx
export const Route = createFileRoute("/")({
  beforeLoad: () => {
    throw redirect({ to: "/practice" });
  },
});
```

`redirect` は戻り値ではなく `throw` で使う。TanStack Router の決まりで、`notFound()` も同じ書き方をする。

## `__root.tsx` は必須

根のルートで、名前も変えられない。消すとビルドが失敗する。すべてのページの外側にあたり、`<Outlet />` の位置に各ページが描かれる。

```tsx
// src/routes/__root.tsx
// component を省くと <Outlet /> だけが描かれる
export const Route = createRootRoute();
```

ヘッダーなどの枠は、ここには置かず、各ページが `components/layouts/` の部品を import して自分で組む（[docs/06](06-コンポーネントの置き方.md)）。ページごとに枠を変えやすくするため。

## `routeTree.gen.ts`

`vite.config.ts` のプラグインが、`src/routes/` を読んで作る。開発サーバーの起動時とビルドのときに作り直される。

```ts
// vite.config.ts
plugins: lazyPlugins(() => [
  // react より前に置く必要がある
  tanstackRouter({ target: "react", autoCodeSplitting: true }),
  react({ compiler: true }),
]),
```

`autoCodeSplitting: true` で、ページごとに JS ファイルが分かれる。開いたページの分だけ読み込まれる。

**コミットする。lint と整形からは外す。**

- 型チェックがこのファイルを読むので、ビルドしていない環境でも型チェックが通るようにコミットする
- 整形しても次の生成で書き戻されるだけなので、`vite.config.ts` の `lint.ignorePatterns` と `fmt.ignorePatterns` で外している。ファイルの冒頭にも「lint と整形から外すように」と書かれている

## URL は `PAGES` から参照する

`Link` や `redirect` の `to` には、URL を直接書かず、`src/constants/pages.ts` の定数を使う。

```ts
// src/constants/pages.ts
import type { FileRoutesByTo } from "~/routeTree.gen";

export const PAGES = {
  HOME: "/",
  PRACTICE: "/practice",
} as const satisfies Record<string, keyof FileRoutesByTo>;
```

```tsx
// Link
<Link to={PAGES.PRACTICE}>練習</Link>

// redirect
throw redirect({ to: PAGES.PRACTICE });
```

- URL が変わったときに、直す場所が 1 か所で済む
- `as const` で、値の型を `string` ではなく `"/practice"` のような文字列そのものにする。`Link` の `to` は実在する URL だけを受け付けるので、`string` に広がると型エラーになる
- `satisfies` で、書いた値が `routeTree.gen.ts` の `FileRoutesByTo`（実在する URL の一覧）に含まれるかを確かめる。`satisfies` は型を確かめるだけで、`as const` で付けた型は変えない。`"/practise"` と書き間違えると、`PAGES` を定義した場所で型エラーになる

```
x typescript(TS2820): Type '"/practise"' is not assignable to type 'keyof FileRoutesByTo'. Did you mean '"/practice"'?
```

`createFileRoute("/practice")` の引数だけは、文字列のまま書く。プラグインがファイルの場所から書き換える値なので、定数にすると生成とずれる。

## 型が効く仕組み

`src/App.tsx` で、ルーターの型を登録している。

```tsx
declare module "@tanstack/react-router" {
  interface Register {
    router: ReturnType<typeof createAppRouter>;
  }
}
```

これで `<Link to="...">` に存在しない URL を書くと、型エラーになる。TS の declaration merging で、ライブラリ側の `Register` に自分のルーターの型を足している。

## App.tsx

ルーターは `App.tsx` で作る。

```tsx
const createAppRouter = () =>
  createRouter({
    routeTree,
    defaultPreload: "intent",
    scrollRestoration: true,
  });

export const App: FC = () => {
  const [router] = useState(createAppRouter);
  return (
    <>
      <RouterProvider router={router} />
      <TanStackRouterDevtools router={router} position="bottom-right" />
    </>
  );
};
```

| 書いているもの              | 理由                                                                                                                               |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `defaultPreload: "intent"`  | リンクにマウスを乗せた時点で、遷移先のページの JS を読み込み始める                                                                 |
| `scrollRestoration: true`   | 戻る・進むで、前に見ていたスクロール位置に戻す                                                                                     |
| `useState(createAppRouter)` | モジュールの一番上ではなくコンポーネントの中で作り、マウントごとに別のルーターにする。テストで何度もマウントしても状態が混ざらない |
| `TanStackRouterDevtools`    | 開発用ツール。本番ビルドでは何も描かないので、環境で分岐する必要はない                                                             |

`useState(createAppRouter)` は、関数を渡すと初回だけ呼ばれる書き方（遅延初期化）。`useState(createAppRouter())` と書くと、描画のたびにルーターを作って捨てることになる。
