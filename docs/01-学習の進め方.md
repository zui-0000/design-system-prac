# 学習の進め方

記録日: 2026-10-13

フロントエンドの UI/UX を勉強するためのリポジトリ。最終的に、React で自分のデザインシステムを作り、Storybook で一覧にする。この文書は、始める前に決めた進め方をまとめたもの。

## やりたいこと

- React を使う
- Vite+（`vp`）を使う
- デザインシステムを作る。UI コンポーネントは Base UI を使って定義する（最初は shadcn/ui も使うつもりだったが、2026-10-20 にやめた。下の「Tailwind と shadcn/ui は使わない」）
- 実践的な形にする。色・z-index・レスポンシブなども設計する
- UX のルールは、手元に用意したものを使う
- UI コンポーネントを Storybook で一覧にする

前提: CSS はほぼ初めて。

## 決めたこと

### Tailwind より先に CSS Modules で基礎を固める

**理由**:

- Tailwind は「CSS をクラス名で書く道具」。`flex`・`gap-4`・`sm:grid-cols-2` はどれも CSS のプロパティに対応している。CSS を知らずに使うと暗記になり、レイアウトが崩れたときに原因が分からない。Spring で言えば、SQL を知らずに JPA を使うのと同じ
- Base UI はスタイルを持たない（headless な）コンポーネント集で、公式ドキュメントに CSS Modules の例がある（[Quick start](https://base-ui.com/react/overview/quick-start)）。CSS Modules の練習の教材にそのまま使える
- ただし shadcn/ui は Tailwind が前提。CSS Modules に長くとどまりすぎない

shadcn/ui は 2026 年 7 月から、新しく作るプロジェクトの標準を Radix から Base UI に切り替えた（[Base UI as the Default](https://ui.shadcn.com/docs/changelog/2026-07-base-ui-default)）。Base UI を先に学んでおくと、shadcn/ui の中身も理解しやすい。

### Tailwind と shadcn/ui は使わない（2026-10-20）

最初は、段階 4 で Tailwind と shadcn/ui も学んで、CSS Modules と比べるつもりだった。段階 3 の途中で見直し、どちらも使わず、Base UI と CSS Modules のまま進めることにした。

**理由**:

- 優先するのは、デザインシステムと CSS の学習。Tailwind は CSS をクラス名で書く道具なので、学ぶことの中心は CSS のほうにある。CSS が分かれば、Tailwind は後から辞書を引くだけで読める
- shadcn/ui の中身は Base UI（上のとおり）。Base UI を CSS Modules で包んでいけば、shadcn/ui がしていることを、自分の手で組むことになる

**手放すもの**: 実務でよく使われる Tailwind と shadcn/ui に慣れる機会。必要になってから覚える。

トークンの名前（`--color-primary` など）は、比べやすいように shadcn/ui に寄せていた（[docs/12](12-デザイントークン.md)）。比べるのはやめたが、名前はそのままにしている。

### 5 段階で進める

| 段階                     | やること                                                                                                                               | 作るもの                                                           | 2026-10-20 の状態           |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | --------------------------- |
| 1. CSS の基礎            | CSS Modules だけで、レイアウトとレスポンシブを練習する                                                                                 | Storybook に素の HTML の部品（カード・一覧・ヘッダーなど）を並べる | 済み                        |
| 2. デザイントークン      | 色・余白・文字サイズ・角丸・影・z-index を CSS 変数（カスタムプロパティ）にする。ダークモードも入れる                                  | Storybook にトークンの一覧ページを作る                             | 済み                        |
| 3. Base UI + CSS Modules | Button・Dialog・Menu・Tooltip などを、自分のトークンでスタイリングする。アクセシビリティや状態の扱いを学ぶ。実践のお題で使う部品も作る | 自分のコンポーネント集                                             | 途中（Button・Switch まで） |
| 4. CSS の仕上げ          | まだ手を付けていない CSS（`@layer` とカスケード、`:has()`、`clamp()` など）を、部品を作りながら押さえる                                | 段階 3 の部品と docs                                               | まだ                        |
| 5. 卒業して、実践        | このリポジトリを離れ、新しいリポジトリで、お題に沿って画面を作る（下の「卒業したら、お題に沿って画面を作る」）                         | お題の画面                                                         | まだ                        |

Storybook は最初から入れて、勉強した成果をそのまま積み上げる。

**2026-10-20 に変更**: 最初の段階 4・5 は、「段階 3 と同じ部品を Tailwind v4 と shadcn/ui（Base UI 版）で作り直して比べる」「最終的なデザインシステムを CSS Modules と Tailwind のどちらで作るか決めて、仕上げる」だった。Tailwind と shadcn/ui を使わないことにしたので（上の「Tailwind と shadcn/ui は使わない」）、上の 4・5 に作り直した。

段階 3 で作る部品は、実践のお題で使うもの（入力欄・Toast・Skeleton・Avatar など）から選ぶ。ここで作った部品を、そのまま実践に持っていけるため。

### 卒業したら、お題に沿って画面を作る（2026-10-20）

ある程度部品がそろったら、このリポジトリを離れ、実際のお題に沿って画面を作る。デザインも本格的なものを考えて進める。

お題の候補は、AI チャットの画面と、X のクローンの SNS。最初は AI チャットにする。画面で起きることに、次に学びたいことがほとんど入っているため。

| 画面で起きること                             | 学べること                                                                              |
| -------------------------------------------- | --------------------------------------------------------------------------------------- |
| 会話の一覧や履歴を読み込む                   | TanStack Query の `useSuspenseQuery`、Suspense、読み込み中の Skeleton                   |
| 読み込みに失敗する                           | Error Boundary と、エラーの画面（`.claude/rules/ux.md` の「エラーの画面も丁寧に作る」） |
| メッセージを送る                             | `useMutation`、送ったメッセージを先に画面に出す（楽観的更新）                           |
| 返答が少しずつ届く                           | ストリーミング、読み上げソフトに届いた分を伝える（`aria-live`）                         |
| 返答の中に部品を出す                         | generative UI。デザインシステムの部品を、AI の返答に合わせて描く                        |
| 入力欄を下に固定し、新しい返答まで自動で送る | `position: sticky`、`dvh`、スマホのキーボードが出たときの高さ                           |

X のクローンでは、タイムラインをどこまでも読み込む（`useSuspenseInfiniteQuery`）、いいねを先に画面に出す、画像の縦横比（`aspect-ratio`）、長い一覧を軽く表示する、などが学べる。

実践に移るときに決めること:

- このリポジトリのデザインシステムをどう持っていくか（コピーする、パッケージにして読み込む、学んだことを元に作り直す）
- AI の返答を、本物の API にするか、テストのための偽物の API にするか（TanStack Query の勉強には偽物でも足りる）

### リポジトリの構成

最初は 1 つのアプリ + Storybook で始める。デザインシステムが育ったら、モノレポ（`packages/ui` に部品を置く）に分けることを考える。

2026-10-20 追記: 実践は、新しいリポジトリで行うことにした。デザインシステムを分けるかどうかは、実践に移るときに決める（上の「卒業したら、お題に沿って画面を作る」）。

### UX のルールは「docs に本体、SKILL から参照」の 2 段構えにする

| 置き場所                                  | 特徴                                                                                         |
| ----------------------------------------- | -------------------------------------------------------------------------------------------- |
| `CLAUDE.md`                               | 毎回必ず読み込まれる。長いルールを書くと、UI と関係ない作業のときに無駄になる                |
| SKILL（`.claude/skills/<名前>/SKILL.md`） | 普段は短い説明文だけが読み込まれ、UI を作るときだけ本文が読まれる。UX のルールの使い方に合う |
| `docs/`                                   | 人間も読める。Storybook のドキュメントページからも参照できる                                 |

ルール本体は `docs/` に置き、SKILL にはいつ使うかと、どのファイルを読むかを書く。shadcn/ui も Claude Code 向けの公式の SKILL を配布しているので（[Skills](https://ui.shadcn.com/docs/skills)）、組み合わせて使える。

**2026-10-15 に変更**: Claude に読ませるルールは、SKILL ではなく `.claude/rules/ux.md` に置いた。SKILL は Claude が関係あると判断したときしか読まれないが、`.claude/rules/` は `paths` に合うファイルを触れば必ず読まれる。ルールは [UIデザイン心理学辞典](https://ui-psychology-dictionary.pages.dev/) をもとに作った。理由と仕分けは `docs/03-UX のルール.md` にまとめた。

## CSS で勉強すること

1. **ボックスモデル**: `box-sizing`、margin・padding・border、margin の相殺
2. **レイアウト**: 通常のフロー、**Flexbox と Grid**（一番大事）、`position`
3. **単位**: `rem` / `em` / `%` / `vw` / `dvh`、`clamp()`（画面幅に合わせて文字サイズをなめらかに変える）
4. **カスケード**: 詳細度、継承、`@layer`（Tailwind v4 も中で使っている）
5. **CSS 変数と色**: デザイントークンの土台。色は「基本の色 → 意味のある色（`--color-danger` など）」の 2 段にする。`oklch()`、`color-mix()`、ダークモードの `prefers-color-scheme` / `light-dark()`
6. **レスポンシブ**:
   - スマホの画面から先に作る（モバイルファースト）
   - メディアクエリ
   - **コンテナクエリ**: 画面幅ではなく、置かれた場所の幅で部品のレイアウトを変える。デザインシステムの部品では特に大事
   - Grid の `auto-fit` と `minmax()`
   - 画像の `aspect-ratio` / `object-fit`
   - タップしやすい大きさ、`prefers-reduced-motion`
7. **スタッキングコンテキストと z-index**: `z-index: 9999` が効かないことがある理由。z-index は「ドロップダウン < 固定ヘッダー < モーダル < トースト」のように、意味ごとに段階を決めてトークンにする。Base UI のドキュメントには、ポップアップを確実に最前面に出すため、アプリのルートの要素に `isolation: isolate` を付けるよう書かれている
8. **状態とアクセシビリティ**: `:focus-visible`、`:has()`、`data-*` 属性での状態の表現、文字と背景のコントラスト

教材:

- [web.dev: Learn CSS](https://web.dev/learn/css)
- [web.dev: Learn Responsive Design](https://web.dev/learn/design)
- [MDN: CSS](https://developer.mozilla.org/ja/docs/Web/CSS)

## ツールの決まり

- **依存のインストールは `vp install`**。`pnpm install` は直接実行しない。`vp install` が `package.json` の `devEngines.packageManager` を読み、指定どおりのバージョンの pnpm を動かすため
- **React Compiler は Rust 版**（`oxc-transform-react` + `react({ compiler: true })`）で有効にし、React Compiler 系の lint ルールは error にした。違反があると Compiler が最適化をスキップするため
- **Node.js のバージョンは `package.json` の `devEngines.runtime` に書き、`onFail` を `"error"` にする**。`"download"` のままだと、pnpm も Node.js をダウンロードして二重管理になる。`.node-version` でもよいが、ルートに `package.json` があるなら `devEngines` にまとめられる
- **`vp run` のキャッシュを有効にするなら、`tsc` は `cache: false` にする**。TypeScript 7 の `tsc` は、キャッシュの自動追跡が効かず、型エラーを見逃す
- **Vite+ の更新は `vp upgrade` → `vp migrate`** の順
