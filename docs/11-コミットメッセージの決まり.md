# コミットメッセージの決まり

記録日: 2026-10-18

[commitlint](https://commitlint.js.org/) で、コミットメッセージの形を検査する。決まりは [Conventional Commits](https://www.conventionalcommits.org/ja/v1.0.0/)。

## 形

```
<type>(<scope 任意>): <説明>

<本文 任意>
```

```
feat: ヘッダーを作る
docs(readme): セットアップ手順を書く
```

| type       | 使う場面                                             |
| ---------- | ---------------------------------------------------- |
| `feat`     | 機能や部品を足す                                     |
| `fix`      | 不具合を直す                                         |
| `docs`     | ドキュメントだけを変える                             |
| `refactor` | 動きを変えずにコードを整理する                       |
| `style`    | 整形だけ（空白・セミコロンなど）。CSS のことではない |
| `test`     | テストを足す・直す                                   |
| `chore`    | 上のどれにも当たらない作業（設定・依存の追加など）   |
| `build`    | ビルドの仕組みや依存を変える                         |
| `ci`       | CI の設定を変える                                    |
| `perf`     | 速くする                                             |
| `revert`   | コミットを取り消す                                   |

## Vite+ に commitlint は入っていない

Vite+ に入っているのは、Git フックを動かす仕組み（`vp hooks`）と、ステージしたファイルを検査する `vp staged` まで。コミットメッセージを検査する機能はない。

ただし、フックの仕組みは pre-commit 以外のフックも動かせる。`.vite-hooks/_/` に Git の全フックの入口（`commit-msg` など）があり、`.vite-hooks/<フック名>` というファイルがあれば、それを実行する。husky と同じ仕組み。

そこで、`.vite-hooks/commit-msg` を置いて、commitlint を呼んでいる。

```sh
# .vite-hooks/commit-msg
commitlint --edit "$1"
```

- `$1` は、Git が渡すコミットメッセージのファイルのパス
- フックの入口が `node_modules/.bin` を `PATH` に足しているので、`commitlint` とだけ書けば動く

## コミット時の流れ

```
git commit
  ├─ .vite-hooks/pre-commit  → vp staged（整形・lint・型チェック・依存の検査）
  └─ .vite-hooks/commit-msg  → commitlint（メッセージの形）
```

どちらかが失敗すると、コミットは止まる。

```
⧗   --- input ---
ヘッダーを作る
✖   subject may not be empty [subject-empty]
✖   type may not be empty [type-empty]
✖   found 2 problems, 0 warnings
VITE+ - commit-msg script failed (code 1)
```

エラーの文言は英語のまま。

## 既定から変えたところ

`commitlint.config.js` で、`@commitlint/config-conventional` を元に、次のルールを無効にしている。

| ルール                                                                | 既定                     | 無効にした理由                                                                  |
| --------------------------------------------------------------------- | ------------------------ | ------------------------------------------------------------------------------- |
| `header-max-length`・`body-max-line-length`・`footer-max-line-length` | 1 行 100 文字まで        | 日本語は 1 文字の情報量が多く、本文の折り返しで引っかかりやすい                 |
| `subject-case`                                                        | 説明の先頭の大文字を禁止 | 「feat: UI を直す」のように、英大文字の略語で始まる日本語の説明も弾かれてしまう |

試した結果。

| メッセージ                 | 結果 | 理由                                                         |
| -------------------------- | ---- | ------------------------------------------------------------ |
| `feat: ヘッダーを作る`     | OK   |                                                              |
| `docs(readme): 手順を書く` | OK   | scope は任意で、名前も自由                                   |
| `feat: UI を直す`          | OK   | `subject-case` を無効にしたため                              |
| `ヘッダーを作る`           | NG   | type がない                                                  |
| `feature: ヘッダーを作る`  | NG   | `feature` は type の一覧にない                               |
| `fix: 直す.`               | NG   | 説明の末尾の半角ピリオドは禁止（全角の「。」は検出されない） |

これまでのコミット（最初のコミットから `65c82ef` まで）も、すべて決まりに合っていた。

## 設定ファイルを `.js` にした理由

dependency-cruiser のときは、コメントを書くために `.jsonc` にした。commitlint の設定は JSON（`.commitlintrc.json`）でも書けるが、コメントを書ける形式として JS を選んだ。`package.json` が `"type": "module"` なので、`export default` で書ける。`@commitlint/types` の型を JSDoc で付けているので、エディタで補完が効く。
