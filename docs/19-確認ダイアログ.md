# 確認ダイアログ

記録日: 2026-10-21 / 対象: Base UI 1.9.0（`@base-ui/react`）、Storybook 10.6.2、Vite+ 1.3.0

段階 3 の 3 つ目の部品。削除などの取り消せない操作の前に、確認を挟むダイアログ（`ui/AlertDialog`）を作った。`.claude/rules/ux.md` の「取り消せない操作」を、部品にしたもの。

- 削除・退会・送金・公開・権限の変更などは、確認を挟む
- 確認の画面では、何が起きるかと、キャンセルの方法をはっきり示す

`/practice` のカードに「削除」を置き、押すと確認してからカードが消えるようにした。

### 消す処理を、ダイアログの中に持たせた

最初は、ページの中でパーツを組み立てていた。文言やボタンの並びまでページに書くと、カードの削除の決まりがページに散らばるので、まず `features/Card/DeleteConfirmDialog` に移した。

次に、消す処理をどこに持つかを考えた。

| 案                                    | ページの書き方                                                                 | 一覧を持つ場所            |
| ------------------------------------- | ------------------------------------------------------------------------------ | ------------------------- |
| A: 消す処理を props で渡す            | `<DeleteConfirmDialog title={card.title} onDelete={() => deleteCard(card)} />` | ページの `useState`       |
| B: ダイアログの中で消す（これにした） | `<DeleteConfirmDialog card={card} />`                                          | `features/Card/` のストア |

A は React の基本の形（状態は持っている人が変え、子は `onDelete` で「消して」と頼むだけ）。ただし、ページが一覧を持つので、ダイアログの中では消せない。

B にするには、一覧をページの外に出す必要がある。配色（[docs/15](15-ダークモードを切り替える.md)）と同じく、React を使わないストア（`utils/cards.ts`）と、それを読む hook（`hooks/useCards.ts`）に分けた。一覧はページ（並べる）と `DeleteConfirmDialog`（消す）の 2 つの部品が使うので、部品のフォルダではなく `features/Card/` の直下に置いた（[docs/06](06-コンポーネントの置き方.md) の「hook と utils の置き場所」）。

実践のお題で TanStack Query を使うようになると、一覧はサーバーと TanStack Query のキャッシュが持つ。`DeleteConfirmDialog` の中で `useMutation` を呼んで消し、キャッシュを捨てて取り直せば、一覧も新しくなる。B は、その形に近い。Spring で言えば、`ui/AlertDialog` は汎用の部品、`DeleteConfirmDialog` は「カードを削除する」ユースケース、`utils/cards.ts` はリポジトリに近い。

- ストアの状態は、変えるたびに新しいオブジェクトに置き換える。`useSyncExternalStore` は、前と同じオブジェクトなら「変わっていない」と判断して描き直さないため（単体テストで確かめている）
- ストアは、モジュール（ファイル）の中に一覧を持つ。ページを離れて戻っても、削除したカードは消えたまま。再読み込みすると元に戻る
- 消したあとの「削除しました」とフォーカスの移動は、ページに残した。消したあとにどこへ移すかは、ページの作りで決まるため。ページは、ストアの「最後に削除したカード」（`lastDeletedCard`）を見て知る

`DeleteConfirmDialog` はスタイルを持たないので、`index.module.css` は置いていない。

`features/Card/utils/__tests__/cards.test.ts` に 5 件書いた（最初の一覧、削除すると外れる、新しいオブジェクトになる、知らせる、登録を外すと知らせない）。

## Dialog ではなく AlertDialog を包む

Base UI には、Dialog と AlertDialog がある。AlertDialog は、Dialog と同じ部品に、3 つの決まりを固定したものだった（`node_modules/@base-ui/react/dialog/root/useRenderDialogRoot.js` で、`mode === 'alert-dialog'` のときに値を固定している）。

|                                      | Dialog         | AlertDialog                           |
| ------------------------------------ | -------------- | ------------------------------------- |
| 読み上げソフトに伝える役割（`role`） | `dialog`       | `alertdialog`（返事が要る、と伝わる） |
| 外側（後ろの幕）を押したとき         | 閉じる         | **閉じない**（うっかり閉じない）      |
| ほかの所を触れなくする（`modal`）    | 切り替えられる | いつも有効                            |
| Esc キー                             | 閉じる         | 閉じる                                |

確認は、ユーザーに返事をもらうためのものなので、AlertDialog にした。外側を押して閉じられると、「削除したのか、しなかったのか」が分かりにくい。

`modal` が有効なので、開いている間は次のようになる（Base UI が受け持つ）。

- フォーカスはダイアログの中に閉じ込められる。Tab で進んでも外に出ない
- ページはスクロールしない。外側の要素は押せない

## 部品の形: パーツに分けた

Card と同じく、パーツに分けた。

```tsx
<AlertDialog trigger={<Button>削除</Button>}>
  <AlertDialogTitle>「4 枚目」を削除しますか？</AlertDialogTitle>
  <AlertDialogDescription>
    削除すると、元に戻せません。キャンセルすると、何も変わりません。
  </AlertDialogDescription>
  <AlertDialogActions>
    <AlertDialogCancel>キャンセル</AlertDialogCancel>
    <AlertDialogAction onClick={handleDelete}>削除する</AlertDialogAction>
  </AlertDialogActions>
</AlertDialog>
```

| パーツ                   | 中身（Base UI）                                  | 役目                                                                   |
| ------------------------ | ------------------------------------------------ | ---------------------------------------------------------------------- |
| `AlertDialog`            | `Root`・`Trigger`・`Portal`・`Backdrop`・`Popup` | 開け閉めと、画面の真ん中に出す枠。`trigger` に押すボタンを渡す         |
| `AlertDialogTitle`       | `Title`（`<h2>`）                                | 何をするかを、問いかけの形で書く。ダイアログの名前として読み上げられる |
| `AlertDialogDescription` | `Description`（`<p>`）                           | 押すと何が起きるかと、キャンセルするとどうなるか                       |
| `AlertDialogActions`     | `<div>`                                          | ボタンを右に寄せて並べる                                               |
| `AlertDialogCancel`      | `Close` + `Button`                               | 何もせずに閉じる                                                       |
| `AlertDialogAction`      | `Close` + `Button`（`variant="danger"`）         | 操作を実行して閉じる。公開などは `variant="primary"`                   |

もう 1 つの案は、1 つの部品に `title`・`description`・`confirmLabel`・`onConfirm` を渡す形（`ConfirmDialog`）だった。キャンセルを置き忘れることがない代わりに、中身を自由に組めない。パーツに分ける形にしたので、**キャンセルを置き忘れないことは、使う側が守る**。

### キャンセルを先に置く

Base UI は、開いたときに、中の最初のフォーカスできる要素にフォーカスを移す。キャンセルを先に置けば、開いた直後に Enter を押しても、削除されない。ux.md の「削除などの取り消せない操作は、押しやすい場所に大きく置かない」と同じ考え方。

閉じると、フォーカスは開いたボタン（`trigger`）に戻る。

### `trigger` は `render` で渡す

```tsx
<BaseAlertDialog.Trigger render={trigger} />
```

`render` に要素を渡すと、Base UI はその要素を描き、開け閉めに要る属性（`aria-haspopup`・`onClick` など）を足す。`<Button>` の中にもう 1 つ `<button>` を作らずに済む。`AlertDialogCancel`・`AlertDialogAction` も同じく、`Close` の `render` に `<Button />` を渡して、見た目をそろえた。

## 見た目

### 色のトークンを 2 つ足した

| トークン                         | 明るい配色   | 暗い配色         | 使う場所                 |
| -------------------------------- | ------------ | ---------------- | ------------------------ |
| `--color-destructive`            | 赤 800       | 赤 400           | 「削除する」の背景       |
| `--color-destructive-foreground` | 白（4.60:1） | 灰 900（6.51:1） | 「削除する」の文字       |
| `--color-overlay`                | 黒 30%       | 黒 50%           | ダイアログの後ろに敷く幕 |

- 赤は `--color-error`（エラーの文字）と同じ材料だが、役目が違う（あちらは文字、こちらは背景）ので分けた。名前は `--color-primary` と同じく shadcn/ui に寄せた
- コントラストは、ブラウザで計算された色から測った。白の文字は 4.60:1 で、4.5:1 をぎりぎり超える
- 幕は、暗い配色ではページがもともと暗いので、濃くしないとダイアログとの差が出ない

`Button` に `variant="danger"` を足した。**確認ダイアログの中でだけ使う**。ページに赤いボタンを直接置くと、確認を挟まずに消せるように見えるため。

### 画面の真ん中に置く

```css
.popup {
  position: fixed;
  top: 50%;
  left: 50%;
  translate: -50% -50%;
  width: min(28rem, 100vw - var(--spacing-16) * 2);
}
```

- `position: fixed` で、画面（スクロールしても動かない枠）を基準にする
- `top: 50%`・`left: 50%` で、ダイアログの左上を画面の真ん中に置き、`translate: -50% -50%` で、自分の幅と高さの半分だけ戻す。これで、ダイアログの真ん中が画面の真ん中に来る
- 幅は、広い画面では 28rem まで、狭い画面では左右に 16px ずつあける。`min()` は、渡した値（カンマで区切って、いくつでも渡せる）のうち、一番小さいものを使う。`min()`・`max()`・`clamp()` の中では、`calc()` を付けずに `+`・`-`・`*`・`/` で計算できる。320px の画面で、x = 16、幅 = 288 になり、横にはみ出さなかった

### 重なりの順番（z-index と isolation）

幕と本体には `z-index: var(--z-index-modal)`（300）を付けた。z-index のトークンを部品で使ったのは、これが初めて。

あわせて、`global.css`（2026-10-26 からは `main.css`）でアプリの外枠（`#root`）に `isolation: isolate` を付けた（Base UI の Quick start に書いてある）。

```css
#root {
  isolation: isolate;
}
```

z-index は、「重なりの区切り（スタッキングコンテキスト）」の中でだけ比べられる。`isolation: isolate` は、z-index を変えずに区切りだけを作る。

- ダイアログは、Base UI が `<body>` の直下（`#root` の外）に出す（ポータル）
- `#root` を区切りにすると、アプリの中で `z-index: 9999` を付けた要素があっても、その値は `#root` の中でしか比べられない。`#root` の外に出たダイアログより上には出ない

TS で言えば、名前空間に近い。`#root` の中の z-index は、`#root` という名前空間の中だけで効き、外のダイアログとはぶつからない。

### 出るとき・消えるときの動き

Base UI は、出始めに `data-starting-style`、消え始めに `data-ending-style` を付ける。その間だけ薄く、少し小さくしておくと、`transition` で、ふわっと出て、ふわっと消える。動きを減らす設定の人には付けない（`prefers-reduced-motion`）。

暗い配色では影がほとんど見えないので（[docs/12](12-デザイントークン.md)）、枠線（`--color-border`）でも形を見せた。

## 削除したあとのフォーカス

キーボードだけで削除すると、フォーカスが `<body>` に落ちた。ダイアログを開いた「削除」ボタンが、カードごと消えたため。閉じたあとの戻り先がなくなり、キーボードの人は今どこにいるか分からなくなる。

`/practice` のページで、次のようにした。

- 削除したら、ページの見出し（`<h1 tabIndex={-1}>`）にフォーカスを移す。`tabIndex={-1}` は、Tab では止まらないが、プログラムからはフォーカスできる
- 2026-10-26 に kiso.css を入れてから、見出しにフォーカスの輪は出ない（`[tabindex="-1"]:focus` の `outline: none`）。フォーカスの場所は変わらないので、次の Tab は見出しの後ろから進む（[docs/12](12-デザイントークン.md) の「リセットは kiso.css に任せた」）
- 「「4 枚目」を削除しました。」を、`role="status"` の段落に出す。中身が変わると、読み上げソフトが読む。中身が変わる前から置いておかないと読まれないので、最初から空で置いている

これはページの側の仕事にした。消したあとにどこへフォーカスを移すかは、ページの作りで決まるため（次のカード、一覧の見出しなど）。

## play 関数で動きを確かめる

ストーリーに `play` 関数を書き、`vp test` で、本物の Chromium の中で操作して確かめるようにした。play 関数を書いたのは、これが初めて（[docs/16](16-単体テスト.md) の「ストーリーのテストで分かること」）。

| ストーリー                 | 確かめること                                                         |
| -------------------------- | -------------------------------------------------------------------- |
| `Default`・`Open`          | 閉じているとき・開いたときの見た目を、アクセシビリティの検査にかける |
| `FocusMovesInAndBack`      | 開くとキャンセルにフォーカスが移り、Esc で閉じると「削除」に戻る     |
| `FocusStaysInside`         | Tab で進んでも、フォーカスがダイアログの中から出ない                 |
| `OutsideClickDoesNotClose` | 外側を押しても閉じない                                               |
| `ConfirmRunsAction`        | 「削除する」を押すと、処理を呼んでから閉じる                         |
| `CancelDoesNothing`        | キャンセルを押すと、何も呼ばずに閉じる                               |

```tsx
play: async ({ canvasElement }) => {
  const trigger = within(canvasElement).getByRole("button", { name: "削除" });
  await userEvent.click(trigger);

  const dialog = await screen.findByRole("alertdialog", { name: "「4 枚目」を削除しますか？" });
  await waitFor(() => expect(within(dialog).getByRole("button", { name: "キャンセル" })).toHaveFocus());
  ...
},
```

- ダイアログは `<body>` の直下に出るので、ストーリーの枠（`canvasElement`）の中ではなく、`screen`（ページ全体）から探す
- 探し方は、見た目ではなく役割と名前（`getByRole("alertdialog", { name })`）。読み上げソフトに伝わっていることも一緒に確かめられる

### 時々落ちたテストと、直し方

`FocusStaysInside` が、3 回に 2 回くらい落ちた。

1. 開いた直後に Tab を押すと、フォーカスがまだキャンセルに移りきっていなかった。キャンセルにフォーカスが来るのを `waitFor` で待ってから押すようにした
2. 最後のボタンから Tab で進むと、Base UI の見えない番人（`data-base-ui-focus-guard` の付いた `<span>`）にいったん止まり、番人がフォーカスを最初のボタンに戻す。戻るのを `waitFor` で待つようにした

直したあとは、5 回続けて通った。フォーカスは、移るまでに少し時間がかかることがあるので、すぐに `expect` せず、`waitFor` で待つ。

### わざと壊して確かめた

| 壊し方                                                 | 失敗したストーリー                                                |
| ------------------------------------------------------ | ----------------------------------------------------------------- |
| AlertDialog の代わりに Dialog を包む                   | 開いたあとを見る 5 つすべて（`alertdialog` の役割が見つからない） |
| 開いてもフォーカスを移さない（`initialFocus={false}`） | `FocusMovesInAndBack`・`FocusStaysInside`                         |
| キャンセルを、閉じないただのボタンにする               | `CancelDoesNothing`                                               |

Dialog に変えた直後の 1 回目は、テストが 1 つも読み込まれなかった（新しく import したパッケージを、Vite が組み直していたため）。もう一度動かすと、上のとおり失敗した。

## 残っていること

- **一覧を API から読む形に整理する**: 今の `utils/cards.ts` は、練習ページのために、メモリの中に一覧を持つ仮の置き場。責務を分けようとすると、一覧を読む側（ページ）と消す側（`DeleteConfirmDialog`）のどちらに置くかで迷う（2026-10-21 に話した）。実践のお題で、TanStack Query と MSW（テスト・開発用の偽物の API）を入れ、一覧は `useSuspenseQuery`、削除は `useMutation` で API として呼ぶ形にすれば、ストアを手で持たなくてよくなり、置き場所も素直に決まる
- **時間のかかる削除**: 今は「削除する」を押すとすぐ閉じる。サーバーに消してもらうなど時間がかかるときは、閉じずに「削除しています」を出し、終わってから閉じる（ux.md の「待ち時間」）。実践のお題（TanStack Query の `useMutation`）で使う
- **名前を入力させる確認**: ux.md の「影響が大きいものは、対象の名前を入力させる」。入力欄（Input）を作ってから
- ~~**「削除」ボタンの置き方**~~: 2026-10-21 に、カードのメニュー（`CardActionsMenu`）の「削除…」にしまった（[docs/21](21-Menu.md)）。`DeleteConfirmDialog` は、開くボタンを持たず、`open`・`onOpenChange` で開け閉めする形に変えた
