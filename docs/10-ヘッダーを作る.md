# ヘッダーを作る

記録日: 2026-10-18

段階 1 でヘッダー（`src/components/layouts/Header/`）を作ったときに学んだこと。

## 構成

```
src/components/layouts/Header/
├── Header.tsx          ロゴ + ナビゲーション（練習・GitHub）
└── Header.module.css
```

ヘッダーは `layouts/` に置き、各ページが自分で import して使う。`src/routes/__root.tsx` には置かない。ページごとに枠を変えやすくするため（[docs/06](06-コンポーネントの置き方.md)・[docs/07](07-ルーティング.md)）。

```tsx
// src/components/pages/Practice/index.tsx
export function PracticePage() {
  return (
    <>
      <Header />
      <main className={styles.page}>...</main>
    </>
  );
}
```

`<main>` は 1 ページに 1 つだけにする。スクリーンリーダーは `<main>` を「本文」として扱い、そこへ移動する機能を持っている。2 つあると、どちらが本文か判断できない。

### 枠をページが持つか、`__root` が持つか

|                            | 良いところ                                                             | 気をつけること                                                                   |
| -------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| ページが枠を持つ（今の形） | ログイン画面だけヘッダーなし、のように、ページごとに枠を変えやすい     | ページを作るたびに `<Header />` を書く。ページを移動すると Header も作り直される |
| `__root` が枠を持つ        | 1 か所に書けば全ページに付く。ページを移動しても Header はそのまま残る | 枠のないページを作るには、ルートを分ける工夫が要る                               |

今の Header は状態を持たないので、作り直されても困らない。検索欄やメニューの開閉を入れると、ページを移動したときに入力や開閉の状態が消える。そのときに見直す。

## 両端に寄せる: `justify-content: space-between`

```css
.header {
  display: flex;
  justify-content: space-between; /* ロゴは左端、ナビゲーションは右端 */
  align-items: center; /* 高さの違うロゴとリンクを、縦の真ん中でそろえる */
}
```

`space-between` は、余った横の空きを**アイテムの間**に全部入れる。アイテムが 2 つ（ロゴと `nav`）なら、左端と右端に分かれる。

## 入りきらなければ折り返す: `flex-wrap: wrap`

初期値の `nowrap` だと、狭い画面でも 1 行に押し込もうとして、はみ出したり潰れたりする。`wrap` にすると、入りきらないアイテムが次の行に回る。

### `gap` に値を 2 つ書く

```css
gap: 0.5rem 1.5rem; /* 行と行の間、アイテムとアイテムの間 */
```

折り返したときの縦の隙間は狭く、横に並ぶロゴと `nav` の間は広く、と分けられる。

### 実際に測った結果

| 画面の幅        | ヘッダーの高さ | 並び方                                               |
| --------------- | -------------- | ---------------------------------------------------- |
| 1280px          | 69px           | ロゴが左端、リンクが右端                             |
| 375px（スマホ） | 69px           | 1 行に収まる（下の「コンテナクエリで余白を詰める」） |
| 320px・240px    | 104px          | リンクがロゴの下に折り返す                           |

どの幅でも、横のはみ出しはなかった。

## コンテナクエリで余白を詰める

外部リンクに ↗ を付けたら、リンクの幅が広がり（75px → 91px）、幅 375px で 2 行に折り返すようになった。そこで、ヘッダーが狭いときだけ余白を詰めて、1 行に収めた。

```css
.header {
  container: header / inline-size; /* このヘッダーを「コンテナ」にする */
}

@container header (width < 30rem) {
  .inner {
    column-gap: 0.75rem; /* 1.5rem → 0.75rem */
  }

  .link {
    padding: 0 0.5rem; /* 0.75rem → 0.5rem */
  }
}
```

- **コンテナクエリ**は、画面の幅ではなく、**コンテナ（置かれた要素）の幅**を条件にする。メディアクエリ（`@media (width < 30rem)`）は画面の幅を条件にする
- `container: header / inline-size` は、「`header` という名前で、横幅を条件に使えるコンテナにする」という意味。`inline-size` は横書きのときの横幅
- **コンテナ自身は、条件で見た目を変えられない。** 自分の幅で自分の幅を変えると、条件がぐるぐる回るため。そこで、`<header>` をコンテナにして、中に `<div class="inner">` を足し、flex はそちらに付けた
- 条件の `30rem` も rem なので、ユーザーが文字を大きくすると、境目も一緒に広がる

測った結果、ヘッダーの幅が 480px までは元の余白（24px）、479px からは詰めた余白（12px）になった。375px では 1 行に収まり、320px より狭いと、これまでどおり 2 行に折り返す。リンクの高さは、どの幅でも 44px のまま。

### ヘッダーならメディアクエリでもよかった

ヘッダーは画面の幅いっぱいに置くので、「ヘッダーの幅」と「画面の幅」はほぼ同じ。今回は、メディアクエリでも同じ結果になる。

コンテナクエリが本当に効くのは、**同じ部品を、幅の違う場所に置くとき**。たとえば Card を、広いメイン欄と狭いサイド欄の両方に置くと、画面の幅は同じでも、Card の幅は違う。メディアクエリでは見分けられないが、コンテナクエリなら置かれた場所の幅で見た目を変えられる。デザインシステムの部品では、こちらが大事になる。

### メディアクエリとコンテナクエリの使い分け

新しいのはコンテナクエリ（主要なブラウザでそろったのは 2023 年）だが、どちらが優れているというより、**見ているものが違う**。今でも両方使う。

|                | 条件にするもの               | 得意なこと                                   |
| -------------- | ---------------------------- | -------------------------------------------- |
| メディアクエリ | **画面**や**ユーザーの環境** | ページ全体の骨組み、ユーザーの設定に合わせる |
| コンテナクエリ | **置かれた場所の幅**         | 部品の中のレイアウト                         |

メディアクエリは、画面の幅以外も条件にできる。次のことは、メディアクエリでしかできない。

```css
@media (prefers-color-scheme: dark) { ... }      /* ダークモードの設定 */
@media (prefers-reduced-motion: reduce) { ... }  /* 動きを減らす設定 */
@media (hover: none) { ... }                     /* マウスがない（タッチだけの）端末 */
@media print { ... }                             /* 印刷するとき */
```

| やりたいこと                                       | 使うもの           |
| -------------------------------------------------- | ------------------ |
| ページ全体の骨組み（サイドバーを出すか、など）     | メディアクエリ     |
| ダークモード、動きを減らす、印刷、タッチ端末       | メディアクエリ     |
| 部品の中のレイアウト（カードを横長にするか、など） | **コンテナクエリ** |

このリポジトリでは、**部品の中はコンテナクエリ、ページとユーザーの設定はメディアクエリ**にする。

### 落とし穴: 中身の幅に縮む要素をコンテナにすると潰れる

`container: ... / inline-size` を付けると、その要素の幅は**中身から決まらなくなる**。「中身で幅が決まり、その幅で中身を変える」とぐるぐる回らないようにするため。

そのため、中身の幅に縮む要素をコンテナにすると、幅が 0 に潰れる。

```css
.row { display: flex; }                        /* 横並びの flex */
.row > .item { container-type: inline-size; }  /* item は中身の幅に縮むはずが、0 になる */
```

横並びの flex アイテムは、何もしなければ中身の幅に縮む（[docs/05](05-px%20と%20rem.md) の「幅の初期値」）。そこをコンテナにすると、中身を見られなくなって潰れる。

コンテナにするのは、**幅が外から決まる要素**にする。ブロック要素、grid のマス、`flex: 1` で伸びる flex アイテムなど。ヘッダーの `<header>` はブロック要素で、画面の幅いっぱいに広がるので問題ない。

## リンクの押せる範囲を 44px 以上にする

```css
.link {
  display: flex; /* <a> はインライン要素で高さを指定できないので、flex にする */
  align-items: center; /* 文字を縦の真ん中に */
  min-height: 2.75rem; /* 44px */
  min-width: 2.75rem;
}
```

`.claude/rules/ux.md` の「押しやすさ」。`<a>` はインライン要素なので、そのままでは `height` が効かない（[docs/05](05-px%20と%20rem.md) の「幅と余白の初期値」）。`display: flex` にすると高さを持てる。

## 今いるページを `aria-current` で目立たせる

```css
.link[aria-current="page"] {
  font-weight: 700;
  background-color: #e8e8ee;
}
```

| 部分                    | 意味                                                             |
| ----------------------- | ---------------------------------------------------------------- |
| `.link`                 | `class="link"` を持つ要素                                        |
| `[aria-current="page"]` | **属性セレクタ**。`aria-current` の値が `"page"` の要素          |
| 間に空白なし            | 両方を満たす同じ要素。空白を入れると「`.link` の中の要素」になる |

`aria-current="page"` は、TanStack Router の `Link` が、今の URL と `to` が一致したリンクに自動で付ける。

```html
<a href="/practice" class="link" aria-current="page" data-status="active">練習</a>
```

`aria-current` は、本来スクリーンリーダーのための属性。「練習、リンク、現在のページ」と読み上げられる。**読み上げ用の属性をそのまま見た目にも使うと、見た目と読み上げが必ず一致する。** `.active` のようなクラスで見た目を変えると、クラスと `aria-current` の 2 つを管理することになり、片方を付け忘れるとずれる。

開閉を `[aria-expanded="true"]`、選択を `[aria-selected="true"]` で見た目に反映するのも同じ考え方。段階 3 の Base UI でも、状態を属性で表す書き方が出てくる。

## 外部リンクは別のタブで開き、そのことを伝える

```tsx
<a href={URLS.GITHUB_REPOSITORY} className={styles.link} target="_blank" rel="noreferrer">
  GitHub
  <span aria-hidden="true">↗</span>
  <span className="global-visually-hidden">（新しいタブで開く）</span>
</a>
```

| 書いたもの                                           | 理由                                                                                                           |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `target="_blank"`                                    | 別のタブで開く                                                                                                 |
| `rel="noreferrer"`                                   | 開いた先に、元のページの URL と `window.opener`（元のタブを操作できる参照）を渡さない。`noopener` の働きも含む |
| `↗`（`aria-hidden="true"`）                          | 目で見て外に出るリンクだと分かる印。読み上げでは「右上矢印」と読まれて邪魔なので外す                           |
| 「（新しいタブで開く）」（`global-visually-hidden`） | 画面には出さず、スクリーンリーダーにだけ読ませる                                                               |

黙って新しいタブを開くと、使う人が迷う。特にスクリーンリーダーの人は、タブが変わったことに気づきにくく、「戻る」が効かずに混乱する。見た目と読み上げの両方で知らせる。

スクリーンリーダーが受け取る名前は「GitHub （新しいタブで開く）」になる（↗ は外れる）。

### 見た目だけを消す: `global-visually-hidden`

```css
/* src/styles/global.css */
.global-visually-hidden {
  position: absolute;
  width: 1px;
  height: 1px;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
}
```

`display: none` や `visibility: hidden` で隠すと、読み上げからも消える。1px に縮めて、はみ出した部分を切り取ることで、見た目だけを消す。

どの部品でも使うので、CSS Modules ではなく `global.css` に置いた。CSS Modules のクラス（`styles.link`）と見分けるため、`global.css` のクラスは名前の先頭に `global-` を付ける。

## URL は定数から参照する

| 定数    | ファイル                 | 中身                                         |
| ------- | ------------------------ | -------------------------------------------- |
| `PAGES` | `src/constants/pages.ts` | ページの URL（`Link` と `redirect` の `to`） |
| `URLS`  | `src/constants/urls.ts`  | 外部サイトの URL                             |

`PAGES` には `satisfies` で、実在する URL だけを書けるようにしている（[docs/07](07-ルーティング.md)）。外部の URL には、実在するかを型で確かめる一覧がないので、`URLS` は `as const` だけ。
